# git-week33-practice
# សំណួរឆ្លុះបញ្ចាំង (Reflection Questions)

### 1. តើ `git clone` និង `git pull` ខុសគ្នាយ៉ាងដូចម្តេច?

Git clone:

* ប្រើសម្រាប់ចម្លងឃ្លាំង Git ទាំងមូលពី Remote Repository (ដូចជា GitHub)  មកកាន់កុំព្យូទ័ររបស់យើង។
* វារួមមានឯកសារ ប្រវត្តិ Commit និង Branches ទាំងអស់។
* ជាទូទៅ ប្រើ `git clone` នៅពេលយើងចង់យក Project មកធ្វើការជាលើកដំបូង។

Git pull:

* ប្រើសម្រាប់ទាញយកការផ្លាស់ប្តូរថ្មីៗពី Remote Repository មកកាន់ Local Repository របស់យើង។
* បន្ទាប់ពីទាញយក វានឹងបញ្ចូល (Merge) ការផ្លាស់ប្តូរទាំងនោះទៅក្នុង Branch ដែលយើងកំពុងប្រើ។
* ជាទូទៅ ប្រើ `git pull` ដើម្បីធ្វើឱ្យ Project របស់យើងទាន់សម័យជាមួយការផ្លាស់ប្តូររបស់អ្នកដទៃ។

### 2. ហេតុអ្វីបានជាអ្នកអភិវឌ្ឍន៍ប្រើ GitHub?

អ្នកអភិវឌ្ឍន៍ប្រើ GitHub ដើម្បី៖

* រក្សាទុកកូដនៅលើអ៊ីនធឺណិត។
* ធ្វើការជាក្រុមជាមួយអ្នកអភិវឌ្ឍន៍ផ្សេងទៀត។
* តាមដានការផ្លាស់ប្តូររបស់កូដ។
* បម្រុងទុក (Backup) Project។
* ចែករំលែក Project ជាមួយអ្នកដទៃ។
* ដោះស្រាយបញ្ហាកូដបានដោយសុវត្ថិភាព តាមរយៈ Version Control និង Branches។
* បង្ហាញជំនាញ និង Project របស់ខ្លួនដល់អ្នកដទៃ។

### 3. ពន្យល់អំពី Git Workflow: Modify → Add → Commit → Push → Pull

Modify (កែប្រែ):

* យើងកែប្រែ ឬបន្ថែមអ្វីមួយនៅក្នុងឯកសាររបស់ Project។

Add (បន្ថែម):

* យើងប្រាប់ Git ថា តើការផ្លាស់ប្តូរណាខ្លះដែលយើងចង់រៀបចំសម្រាប់ Commit ដោយបញ្ចូលវាទៅក្នុង Staging Area។

Commit (រក្សាទុក):

* យើងរក្សាទុកការផ្លាស់ប្តូរដែលបានដាក់នៅក្នុង Staging Area ទៅក្នុង Local Repository និងកត់ត្រាវាទៅក្នុង Git History។

Push (បញ្ជូន):

* យើងបញ្ជូនការផ្លាស់ប្តូរដែលបាន Commit ពី Local Repository ទៅ Remote Repository ដូចជា GitHub ដើម្បីឱ្យសមាជិកក្រុមផ្សេងទៀតអាចមើលឃើញ និងប្រើប្រាស់បាន។

Pull (ទាញយក):

* យើងទាញយកការផ្លាស់ប្តូរថ្មីៗពី Remote Repository មកកាន់ Local Repository ហើយបញ្ចូលវាទៅក្នុង Branch ដែលយើងកំពុងប្រើ ដើម្បីឱ្យ Project របស់យើងទាន់សម័យ។

### 4. តើបញ្ហាអ្វីខ្លះអាចកើតឡើង នៅពេលអ្នកអភិវឌ្ឍន៍ជាច្រើន Push Code ក្នុងពេលតែមួយ?

នៅពេលអ្នកអភិវឌ្ឍន៍ជាច្រើនធ្វើការ និង Push Code ក្នុងពេលតែមួយ អាចមានបញ្ហាដូចជា៖

* Merge Conflict: អ្នកអភិវឌ្ឍន៍ពីរនាក់ ឬច្រើននាក់កែប្រែផ្នែកដូចគ្នានៃ File ដែលអាចបង្កឱ្យមានការប៉ះទង្គិច ហើយត្រូវដោះស្រាយ Conflict។
* Build Problems: ការផ្លាស់ប្តូររបស់អ្នកអភិវឌ្ឍន៍ផ្សេងៗគ្នាអាចមិនដំណើរការជាមួយគ្នា ហើយធ្វើឱ្យ Project Build មិនបាន។
* Bugs: ការផ្លាស់ប្តូររបស់អ្នកអភិវឌ្ឍន៍ម្នាក់អាចបង្កឱ្យផ្នែកផ្សេងទៀតនៃ Project មានបញ្ហា។
* Performance Problems: កូដថ្មីអាចធ្វើឱ្យប្រព័ន្ធដំណើរការយឺត ឬមិនមានប្រសិទ្ធភាព។
* Conflicting Changes: អ្នកអភិវឌ្ឍន៍អាចមាន Version ខុសៗគ្នានៃ Code ដែលធ្វើឱ្យការបញ្ចូលការងាររបស់ពួកគេចូលគ្នាមានភាពស្មុគស្មាញ។
